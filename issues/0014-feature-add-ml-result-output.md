# 文字起こし等の機械学習の推論結果を外部へ出力する仕組みを検討する

- Priority: Low
- Created: 2026-06-03
- Completed:
- Model: Opus 4.8
- Branch: feature/add-ml-result-output
- Polished:

## 目的

0012 で得られる ML 推論結果 (Whisper 文字起こしや、その他の機械学習の出力) を、hisui の外部へ伝えるための出力口を用意する。現状 hisui の出力は合成後のメディアデータ (映像・音声) が中心で、文字起こしテキストのような非メディアデータを外部へ渡す汎用的な手段がほとんど無い。ML 機能 (0012) を実用にするには、推論結果をプログラムから受け取れる経路が必要になる。

## 優先度根拠

- 0012 (ML 推論) に依存し、単体では動かない。0012 のスコープ・成果が固まらないと、出力すべきデータの形も決められない。
- 中身が全くの未検討の段階であり、まずは設計の方向性を探るための issue。
- 以上から現時点では Low。0012 が進み、外部出力の具体ニーズが固まった段階で見直す。

## 現状

- hisui の出力はメディアデータ中心 (MP4 / WebM / HLS / DASH の各 writer、配信経路)。
- 文字起こしテキストのような非メディアデータを外部へ渡す汎用的な口は無い。PR #246 の `ml audio` PoC でも、文字起こし結果はログ出力にとどまる。
- 技術的な可能性としては WebRTC のデータチャネル経由で送る等が考えられるが、その程度で、確立した仕組みは無い。

## 設計方針 (未確定)

中身は未検討。最低限、設計時に次を詰める:

- 何を出力するか: 文字起こしテキスト、タイムスタンプ、物体検出結果などのデータ種別。
- どの形式・経路で出力するか: 標準出力への JSON LINE、ファイル、WebSocket、WebRTC データチャネル等。
- リアルタイム (OBSWS / 配信) と録画合成のどちらを対象にするか。
- 出力データのスキーマ (時刻との対応、信頼度などのメタ情報)。
